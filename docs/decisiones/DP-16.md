## Opciones consideradas

| Opción | Ventajas | Desventajas |
| --- | --- | --- |
| **SQLite** (elegida) | Viene incluido en Python, sin instalación. Un solo archivo. Cada escritura es completa o no ocurre. Permite impedir modificaciones y borrados con disparadores. Se consulta con un visor de SQLite | Para inspeccionarlo hace falta un visor o el comando `suficiencia registro ver` |
| Archivos JSON Lines | Se leen con cualquier editor | Más fácil de dañar o editar a mano; las escrituras parciales son posibles |

## Justificación

La especificación pide que los registros solo admitan agregar (M6) y que cada resultado se pueda reconstruir. SQLite lo garantiza sin dependencias nuevas ni servidores (sección 5.1: sqlite3 era una dependencia condicional de esta decisión).

## Consecuencias

- `workspace/registro.sqlite` queda fuera de git, como todo `workspace/` (RNF-07).
- La implementación es H2.7: `src/suficiencia/persistence/repositorio_sqlite.py`.
- Solo `repositorio_sqlite.py` puede usar sqlite3; el dominio no puede (contrato de import-linter).
